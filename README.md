# wrapps

[en](README.en.md)

Переносимое окружение NixOS и обёрнутые приложения.

## Быстрый старт

```bash
nix run github:solokha/wrapps/main#env
```

## Состав

- `env` — окружение с инструментами и обёрнутыми пакетами
- `shell` — интерактивная оболочка с окружением
- `denv` — прямой запуск окружения
- `desktop` — десктоп целиком
- `noctalia` — коллекция тем

## Пакеты

- Терминал: `foot`, `zellij`, `helix`
- Десктоп: `niri`, `fuzzel`, `zed`
- Браузер: `firefox`
- Инструменты: `git`, `lazygit`, `btop`, `eza`, `ripgrep`, `fzf`
- Агент: `opencode` (v2, из `llm-agents.nix`)

## Секреты

`wrapps` — публичный репозиторий: учётных данных здесь **нет и быть не должно**.
Всё, что попадает в дефолты приложений (агент, модели, тема, шрифты), — несекретно,
и это проверяется при каждой правке.

Где живут секреты, когда появляются:

- **У самих приложений**, в персистентном `$HOME`: например, креды opencode
  (`~/.local/share/opencode`) и пароль его локального сервиса
  (`~/.config/opencode/service.json`). Рядом с репозиторием они не лежат.
- **Zed** держит ключи провайдеров в системном хранилище секретов
  (secret-service / gnome-keyring), а не в `settings.json`. Нет хранилища — ключ
  не сохранится; это вопрос хостовой конфигурации, не wrapps.
- **Per-host значения из окружения**: endpoint'ы и токены приходят в процесс
  переменными, конфиги читают их через `{env:...}` и ничего не вшивают. Несекретная
  часть — в конфиге хоста, секретная — в локальном git-ignored оверлее.

На **чужом хосте или в живом образе** секретов просто нет: wrapps кладёт
несекретные дефолты, а агенты, которым нужны креды, просят логин (opencode ACP —
«Login with opencode», Zed — свой вход). Ничего не ломается и ничего секретного
никуда не разъезжается.

## FIDO2

Ключи FIDO2 используются для доступа по SSH. Окружение поднимает
`wrapps-agent` и подсказывает, когда требуется PIN.

Первый раз нужно восстановить ключи с токена:

```bash
mkdir -p ~/.ssh && cd ~/.ssh && ssh-keygen -K
```

`ssh-keygen -K` скачивает резидентные ключи, пишет обе половины в текущий
каталог и требует касания токена. Дальше `wrapps-ssh-config` подставляет их
в `~/.ssh/config`, если система их ещё не перечисляет сама.

Приватные ключи на диске — только handle-файлы (пустые), сам секрет остаётся
в токене.

## Использование

```bash
# Войти в окружение
nix run github:solokha/wrapps/main#env

# Запустить конкретный инструмент
nix run github:solokha/wrapps/main#env -- git status

# Десктоп
nix run github:solokha/wrapps/main#desktop
```
