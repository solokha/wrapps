# Идеи

## Декларативные контейнеры Firefox (2026-10-25, не реализовано)

Цель: правила «какой домен/URL открывать в каком контейнере» лежат в `wrapps` рядом с
`modules/firefox.nix`, а не задаются руками в аддоне после каждого нового профиля.

Почему штатно нельзя:

- ни в `policies.json`, ни в prefs нет ключей для контейнеров и привязок; декларативно
  доступен только `privacy.userContext.enabled` (сами контейнеры включены);
- Multi-Account Containers держит и контейнеры, и «Always open in» в своём storage внутри
  профиля — Firefox Sync это не переносит (и у нас Sync всё равно выключен политикой
  `DisableFirefoxAccounts`);
- `ext+container:name=…&url=…` — протокол сторонних аддонов (`Open URL in Container` и
  подобных), а не MAC; при нашем `"*" = blocked` они не установятся без исключения.

Возможный путь — свой маленький WebExtension:

- JSON с правилами (домен или префикс URL → имя контейнера) в `wrapps`;
- на старте создаёт контейнеры через `contextualIdentities`;
- переоткрывает вкладки по правилам (`tabs` + `webRequestBlocking`) — так работает MAC;
- ставится через `force_installed` в `ExtensionSettings` из `modules/firefox.nix`;
- бонус к MAC: он умеет привязку только по домену, свой аддон — по префиксу URL.

Открытый вопрос: нужны ли правила вообще, или хватает ручной настройки MAC.
