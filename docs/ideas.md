# Идеи

## Декларативные контейнеры Firefox (2026-10-25, реализовано 2026-11-21)

Цель: правила «какой домен открывать в каком контейнере» задаются декларативно, а не
руками в аддоне после каждого нового профиля.

Реализовано на обычном Firefox 160 (не ESR): политика `SitePolicies` с
`Policies.Container` появилась в Firefox 158. В ESR 153 её нет, поэтому на ESR
вернёмся, когда там будет 158 (следующий ESR, ориентировочно 166).

Как устроено:

- правила — `SitePolicies` в `policies.json`;
- контейнеры создаёт сам Firefox (`createForPolicy`) при старте; это скрытые
  policy-контейнеры (`public: false`, без цвета и иконки), а не контейнеры MAC;
- Multi-Account Containers удалён: он был нужен только для ручного UI и собственных
  привязок;
- механизм — в `modules/firefox.nix`, сами домены — в приватном `infra`
  (NixOS-опция `wrapps.firefox.sitePolicies`), чтобы публичный репозиторий не
  содержал хостовых фактов.

Ограничения:

- `Match` работает по base domain и игнорирует путь: `example.com/app/*` не выразить;
- поддомены одного домена не разделяются;
- policy-контейнеры не видны в интерфейсе контейнеров и не имеют цвета/иконки.

Если понадобятся правила по путям, нужен свой WebExtension с `webRequestBlocking`;
на release такой XPI придётся подписывать на AMO (или ставить в Developer Edition).
