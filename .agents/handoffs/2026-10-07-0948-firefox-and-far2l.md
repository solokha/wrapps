# Handoff: Firefox терял все префы, а файловый менеджер тащил пол-системы

Сессия 2026-10-07. Коммиты в `wrapps`: `d577375` (firefox), `2c87466`
(far2l). Оба запушены в `dev`.

Разбор `/tmp`, `sshd-keygen` и журналов — в приватной документации `infra`,
файл `docs/STATUS.md`.

## 1. Firefox: `Failed to read the configuration file`

Сообщение приходит не из GIO. Оно лежит в
`chrome/en-US/locale/en-US/autoconfig/autoconfig.properties` внутри
`omni.ja`:

```
readConfigMsg = Failed to read the configuration file. Please contact your system administrator.
```

Значит Firefox не смог прочитать свой файл конфигурации — и это
автоконфиг, а не профиль.

`wrapFirefox` реализует `extraPrefs` так: пишет `mozilla.cfg` **дословно**
и выставляет `pref("general.config.filename", "mozilla.cfg")` в
`defaults/pref/autoconfig.js`. То есть `mozilla.cfg` — это сам файл
настроек Firefox, и он обязан быть валидным JavaScript.

В `modules/firefox.nix` два Nix-комментария `#` стояли **внутри** строки
`extraPrefs = ''…''`, и они попадали в `mozilla.cfg` дословно. `#` в
JavaScript не комментарий, парсер отвергал файл целиком, и **все**
`extraPrefs` терялись.

Правило: `extraPolicies` — обычный Nix-атрибутный набор, там `#` законен.
`extraPrefs` — многострочная строка, там `#` попадает в Firefox. Только
`//`.

`extraPolicies` при этом не пострадали: политики лежат в
`distribution/policies.json`, это отдельный механизм, JSON валидный, все
семь `force_installed` расширений на месте. Сломан был только блок
префов. Внёс `86a2ce1`.

## 2. Файловый менеджер: почему ушли thunar и file-roller

### file-roller тянул nautilus

Самое интересное здесь не в самом file-roller, а в его зависимостях:

```
libadwaita-1.9.3 ← zenity, nautilus, file-roller
nautilus-50.2.2  ← file-roller
```

**file-roller тянет за собой целый nautilus** — второй файловый менеджер,
которого в списке пакетов не было и которого никто не просил. Отсюда
1.2 GiB замыкания при 10.3 GiB на всю систему.

Вывод, который стоит держать: **полное рекурсивное замыкание пакета —
не то, что пакет добавляет.** Большинство его веса общее с остальной
системой. Считать надо маргинальную стоимость, а не заголовок.

### thunar был GTK3, и палитра до него не доходит

`thunar-4.20.9` — `gtk+3-3.24.52`. В `libgtk-3.so.0`:

| имя цвета | вхождений |
|---|---|
| `window_bg_color` | **0** |
| `headerbar_bg_color` | **0** |
| `accent_bg_color` | **0** |
| `theme_bg_color` | 4 |
| `theme_selected_bg_color` | 4 |

GTK3 читает семейство `theme_*`. Шаблон GTK3 у noctalia задаёт
libadwaita-овские имена, поэтому из оформления применялось только
выделение. Проверка: выделить файл в thunar — он станет зелёным, всё
остальное останется неоформленным.

GTK4 и libadwaita читают `--accent-color` (104 вхождения в
`libadwaita-1.9.3`), `--window-bg-color` (15) — поэтому GTK4-приложения
оформляются.

**Это опровергло утверждение в комментарии самого `flake.nix`**, который
стоял прямо над списком: «GTK3, поэтому подхватывает gtk.css, который
noctalia генерит из палитры». Комментарий удалён вместе с пакетом.

### far2l собран без GUI

`nixpkgs#far2l` даёт GUI-бэкенд на wxWidgets. По умолчанию это 1.1 GiB и
GTK в дереве. Переопределение в `overlay.nix`:

| вариант | замыкание | пакетов |
|---|---|---|
| по умолчанию (`withGUI = true`) | 1.1 GiB | 285 |
| `withGUI = false` | 593 MiB | 165 |
| **`withGUI = false` + `withNetRocks = false`** | **253.8 MiB** | **102** |
| thunar, для сравнения | 337 MiB | — |

У выбранного варианта **ноль ссылок** на wx/gtk/qt/samba.

Флаги:

- `withGUI = false` — TUI, и тогда вопрос оформления не возникает вовсе:
  палитра noctalia до far2l не доходит, да и не должна.
- `withNetRocks = false` — своя сеть (samba, openssl, libssh, libnfs,
  neon) стоит 340 MiB. smb:// и носители берутся через gvfs,
  смонтированные в `/run/user/1000/gvfs`, оттуда far2l их видит.
- `withMultiArc` остаётся — libarchive даёт просмотр архива изнутри.
  Плюс обёртка nixpkgs кладёт в PATH `gnutar`, `bzip2`, `gzip`, `xz`,
  `p7zip`, `zip`, `unzip`.

Архив открывается штатно: `far2l -cd путь/к/архиву`.

Проверено: `nix flake check`, сборка far2l из overlay, запуск
`far2l --version` → `2.7.0-beta`.

## Ловушка на будущее: палитра не зашивается

Правило, которое стоит удержать: **палитра задаётся noctalia, модули
только транслируют имена.** Для GTK3 это означает генерацию `theme_*` из
`~/.config/gtk-3.0/noctalia.css` в рантайме, а не константы в NixOS — иначе
цвет разъедется при первой же смене палитры.

Источник — файл, который noctalia реально пишет, а не её `config.toml`:
разбор конфига означал бы угадывать чужую схему. Ровно так в аудите
2026-09 появилась ложная причина падения `sshd-keygen`.
