# Решение: quake без foot server / footclient

- Date / host / agent: 2026-11-22 12:11 / rover / opencode
- Goal: зафиксировать, почему quake-терминал запускает обычный foot, а не
  `foot --server` + `footclient`, чтобы не возвращаться к этому без причины.
- Decision: **не переводить quake на foot server**. Оставить прямой запуск foot.

## Как сделано сейчас

- `Mod+grave` запускает `foot --app-id=dropdown` с `tmux new-session -A -s quake`;
- повторное нажатие находит окно по `app-id=dropdown` и закрывает его;
- tmux-сессия остаётся живой, следующее открытие подключается к ней;
- окно floating: 80% ширины, 50% высоты, прижато к верху (window-rule niri).

## Почему не foot server

1. **Тема Noctalia.** Сервер читает конфиг и include-темы при старте. После
   смены палитры его нужно перезапускать, иначе новые окна открываются со
   старыми цветами. У нас тема обновляется шаблоном Noctalia на лету.
2. **Лишний сервис.** Нужен постоянный `foot --server` в сессии, сокет,
   контроль запуска после niri — ещё одна точка отказа.
3. **Выигрыш мал.** Один quake-терминал и редкие `Mod+Return`: запуск foot
   занимает десятки миллисекунд. Разница заметна на десятках терминалов,
   не на нашем сценарии.
4. **tmux уже решает главное.** Процессы и скролл живут в tmux, а не в foot;
   переоткрытие окна и так дешёвое.

## Когда пересмотреть

Если появится много одновременно открытых терминалов и станет важна
мгновенность, можно вернуться к `foot --server` + `footclient`. Тогда
обязательно решить перезагрузку темы: рестарт сервера по сигналу от Noctalia
или отдельный механизм перечитывания конфига.

- How to resume: `wrapps/modules/niri.nix` — `quake`, `binds."Mod+grave"`,
  window-rule `dropdown`.
